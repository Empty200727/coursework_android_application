# Итерации для Claude Code

Проект собирается за 4 итерации. Каждая — отдельная сессия Claude Code, опирается на код предыдущей и заканчивается рабочей сборкой, зелёными тестами и коммитом. После итерации 3 готов весь MVP; итерация 4 — качество и подготовка к сдаче.

> Итерации 1–4 выполнены на Kotlin и Compose, затем по требованию преподавателя приложение переписано на Java
> (итерация 5 в конце документа). Промпты итераций 1–4 сохранены как история; актуальные стек и правила — в `CLAUDE.md`.

| # | Итерация | Требования | Результат |
| --- | --- | --- | --- |
| 1 | Фундамент и данные | F-04, N-03, N-09 | Каркас проекта, сеть, база, справочник жанров, экраны-заглушки |
| 2 | Каталог и поиск | F-01…F-07, N-02, N-04…N-06 | Рабочие «Главная», «Поиск», «Экран жанра» |
| 3 | Карточка и медиатека | F-08…F-14, N-01, N-07 | Полный MVP, медиатека без сети |
| 4 | Качество и сдача | N-08, N-10, критерии раздела 11; F-15…F-18 по остатку времени | UI-тесты, release-сборка, README |

## Подготовка

1. Экспортировать основную вкладку плана в Markdown и положить в репозиторий как `docs/PLAN.md`, эту вкладку — как `docs/ITERATIONS.md`.
2. Получить в кабинете TMDB токен доступа на чтение и добавить в `local.properties` строку `TMDB_TOKEN=...`.
3. Создать в корне репозитория `CLAUDE.md` — Claude Code читает его в начале каждой сессии:

```markdown
# Кинополка

Android-приложение: каталог фильмов и сериалов на TMDB API с офлайн-медиатекой.
Требования и архитектура: docs/PLAN.md (ID требований F-xx, N-xx). Итерации: docs/ITERATIONS.md.

## Стек
Kotlin, Jetpack Compose + Material 3, MVVM, Hilt, Retrofit + OkHttp + kotlinx.serialization,
Coroutines/Flow, Room (KSP), Paging 3, Coil, Navigation Compose (типобезопасные маршруты), WorkManager.

## Правила
- Room — единый источник данных для UI; сеть только обновляет базу.
- Ключ произведения везде — пара (mediaType, tmdbId).
- Один UiState на экран, StateFlow из ViewModel; запрос и фильтры — в SavedStateHandle.
- Пакеты по функциям: feature/*, core/network, core/database, core/data, core/model, core/ui.
- Версии зависимостей только в gradle/libs.versions.toml, стабильные.
- Токен TMDB: local.properties -> BuildConfig. Никогда не коммитить.
- Строки интерфейса — в strings.xml, на русском.
- Не менять схему Room без миграции и теста.
- Новый код покрывать тестами. Перед завершением задачи: ./gradlew assembleDebug testDebugUnitTest lint detekt
```

4. Каждую итерацию начинать в режиме планирования: Claude Code предлагает список файлов и шагов, вы подтверждаете, затем он пишет код. Между итерациями — новая сессия (`/clear`), чтобы контекст не переполнялся.

## Итерация 1. Фундамент и данные

Цель — весь невидимый слой: после итерации приложение запускается с пустыми экранами, но уже умеет ходить в TMDB и хранить данные. Разделы плана: 4, 5, 6.

**Состав**

- [x] Gradle-проект: version catalog, minSdk 26, Hilt, KSP, kotlinx.serialization, detekt и ktlint
- [x] Токен из `local.properties` в `BuildConfig`, проверка `.gitignore`
- [x] Тема Material 3: светлая, тёмная, динамические цвета, edge-to-edge
- [x] Навигация: нижняя панель «Главная / Поиск / Моя полка», маршруты всех 6 экранов с заглушками
- [x] `core/network`: `TmdbApi` со всеми эндпоинтами раздела 4, DTO, интерцептор токена и `language=ru-RU`, повтор при `429`
- [x] `core/database`: все таблицы раздела 6, DAO с `Flow`, `exportSchema = true`
- [x] `core/model` и мапперы DTO → модель → сущность
- [x] Объединённый справочник жанров и `GenreRepository` с кэшем на 7 дней

**Готово, когда:** приложение запускается и переключает вкладки; проходят тесты мапперов и справочника жанров, тесты API на MockWebServer с JSON-фикстурами реальных ответов, тесты DAO.

**Промпт**

```text
Прочитай CLAUDE.md, docs/PLAN.md (разделы 4–6) и docs/ITERATIONS.md.
Выполни итерацию 1 «Фундамент и данные».

1. Создай Android-проект «Кинополка» (package ru.kinopolka, minSdk 26) со стеком из CLAUDE.md.
   Все версии — в gradle/libs.versions.toml, последние стабильные. Подключи detekt и ktlint.
2. TMDB_TOKEN читай из local.properties в BuildConfig.
3. Тема Material 3 (светлая/тёмная, dynamic color), edge-to-edge.
4. Навигация: нижняя панель на 3 вкладки, типобезопасные маршруты Home, Search, Library,
   Details(mediaType, id), Genre(genreKey, filter), About — пока экраны-заглушки.
5. core/network: Retrofit-интерфейс со всеми эндпоинтами раздела 4 плана, DTO с nullable-полями,
   Json { ignoreUnknownKeys = true }, интерцептор Bearer-токена и language=ru-RU, повтор при 429.
6. core/database: все сущности раздела 6 с составным ключом (mediaType, tmdbId), DAO на Flow.
7. Мапперы и объединённый справочник жанров (таблица соответствия id фильмов и сериалов),
   GenreRepository с кэшем 7 дней.
8. Тесты: мапперы, справочник жанров, API на MockWebServer с JSON-фикстурами, DAO (in-memory).

Сначала покажи план файлов и дождись подтверждения. В конце запусти
./gradlew assembleDebug testDebugUnitTest lint detekt, исправь ошибки и сделай коммит
«Итерация 1: фундамент и данные».
```

## Итерация 2. Каталог и поиск

Цель — всё, что пользователь видит до открытия карточки: главная с полками, экран жанра и поиск. Разделы плана: 2 (F-01…F-07), 3, 7.

**Состав**

- [x] `MediaRepository`: подборки и полки через `feed_item`, показ кэша с фоновым обновлением по срокам N-03
- [x] Общие компоненты `core/ui`: карточка постера, горизонтальная полка, скелеты, состояния «пусто» и «ошибка», офлайн-баннер
- [x] Отслеживание сети через `ConnectivityManager` в виде `Flow`
- [x] Главная: поле-кнопка поиска, чипы «Все / Фильмы / Сериалы», «В тренде», популярное, 6–8 полок жанров
- [x] Экран жанра: сетка постеров, Paging 3, сортировка «Популярные / По рейтингу / Новые»
- [x] Поиск: задержка 400 мс, от 2 символов, отмена предыдущего запроса, без персон, Paging 3, фильтр типа, жанры из справочника
- [x] Запрос, фильтр и позиция прокрутки переживают поворот и смерть процесса

**Готово, когда:** с сетью все три экрана грузятся и листаются без рывков; без сети главная показывает кэш и баннер, поиск — понятное сообщение; нажатие на постер открывает заглушку карточки с верными типом и id. Тесты: ViewModel поиска (задержка, отмена, фильтр), политика кэша с подменой времени, объединение полок при фильтре «Все».

**Промпт**

```text
Прочитай CLAUDE.md, docs/PLAN.md (разделы 2, 3, 7) и docs/ITERATIONS.md.
Итерация 1 завершена. Выполни итерацию 2 «Каталог и поиск» — требования F-01…F-07, N-02, N-04…N-06.

1. MediaRepository: подборки (trending/all/week, movie/popular, tv/popular) и полки жанров
   через discover с vote_count.gte=100. Хранение в feed_item; UI читает Room, устаревший кэш
   (6 ч) обновляется в фоне. При фильтре «Все» полка объединяет фильмы и сериалы по популярности.
2. core/ui: PosterCard, Shelf, скелеты загрузки, EmptyState, ErrorState с «Повторить»,
   баннер «Нет подключения». Статус сети — Flow поверх ConnectivityManager.
3. Главная: поле поиска как кнопка (открывает Search с фокусом), чипы фильтра, «В тренде»,
   популярное, 6–8 полок; кнопка «Все» у полки открывает Genre.
4. Экран жанра: LazyVerticalGrid + Paging 3, сортировка популярность / рейтинг / дата.
5. Поиск: search/multi без персон, debounce 400 мс, минимум 2 символа, flatMapLatest,
   Paging 3, чипы фильтра, в строке — постер, название, год, тип, 1–2 жанра из справочника.
6. Один UiState на экран; запрос и фильтр в SavedStateHandle.
7. Тесты: ViewModel поиска (Turbine + kotlinx-coroutines-test), политика кэша, объединение полок.

Сначала план, потом код. В конце: ./gradlew assembleDebug testDebugUnitTest lint detekt,
исправь ошибки, коммит «Итерация 2: каталог и поиск».
```

## Итерация 3. Карточка и медиатека

Цель — закрыть MVP: карточка произведения, списки пользователя и работа без сети. Это самая объёмная итерация; если контекст сессии заканчивается, её можно разделить на 3а (карточка) и 3б (медиатека и офлайн). Разделы плана: 2 (F-08…F-14), 6, 7.

**Состав**

- [x] Детали фильма и сериала одним запросом с `append_to_response`, кэш 24 часа в `media`, `cast_member`, `related_media`
- [x] Похожие: `recommendations`, при пустом ответе — `similar`; описание на английском с пометкой, если русского нет
- [x] UI карточки: все поля F-08, 10 актёров, полка похожих, переключатель «Хочу / Смотрел», кнопка избранного
- [x] `LibraryRepository`: правило статусов, удаление записи при статусе NONE без избранного, сохранение постера в `filesDir/posters`
- [x] «Моя полка»: вкладки со счётчиками, сортировка, фильтр по типу, удаление свайпом с отменой, пустое состояние
- [x] WorkManager: ежедневная очистка кэша старше 30 дней, не затрагивающая медиатеку
- [x] «О приложении»: версия, логотип и уведомление TMDB, ссылка на themoviedb.org

**Готово, когда:** сценарий «найти → открыть карточку → «Хочу» → «Смотрел» → «В избранное» → режим полёта → «Моя полка» с постерами → открыть сохранённую карточку» проходит без ошибок. Тесты: правило статусов, очистка кэша не удаляет записи медиатеки, запасной `similar`.

Логотип TMDB нужно заранее скачать со страницы одобренных логотипов TMDB и положить в `app/src/main/res/drawable` — Claude Code не должен рисовать его сам.

**Промпт**

```text
Прочитай CLAUDE.md, docs/PLAN.md (разделы 2, 6, 7) и docs/ITERATIONS.md.
Итерации 1–2 завершены. Выполни итерацию 3 «Карточка и медиатека» — F-08…F-14, N-01, N-07.

1. Детали: movie/{id}?append_to_response=credits,recommendations,similar и
   tv/{id}?append_to_response=aggregate_credits,recommendations,similar. Сохранение в media,
   cast_member, related_media; кэш 24 ч. Похожие — recommendations, при пустом ответе similar.
   Нет русского описания — повторный запрос en-US и пометка «Описание на английском».
2. Экран Details: фон и постер, название и оригинальное название, год, тип, рейтинг с числом
   голосов, жанры, раскрывающееся описание; фильм — длительность, сериал — годы и число сезонов;
   10 актёров; полка похожих. Без сети — данные из кэша.
3. LibraryRepository и library_entry: watch_status NONE/WANT/WATCHED взаимоисключающие,
   is_favorite независим; запись удаляется при NONE без избранного. При добавлении постер
   сохраняется в filesDir/posters, путь — в local_poster_path; при удалении файл стирается.
4. Экран Library: вкладки «Хочу», «Смотрел», «Избранное» со счётчиками, сортировка
   (дата, название, рейтинг), фильтр типа, свайп-удаление с Snackbar «Отменить», пустое состояние.
5. WorkManager: ежедневно удалять из media записи старше 30 дней без ссылки из library_entry.
6. Экран About: версия, логотип R.drawable.tmdb_logo (файл уже в проекте), текст
   «This product uses the TMDB API but is not endorsed or certified by TMDB.», ссылка на сайт.
7. Тесты: правило статусов, очистка кэша, запасной similar.

Сначала план, потом код. В конце: ./gradlew assembleDebug testDebugUnitTest lint detekt,
исправь ошибки, коммит «Итерация 3: карточка и медиатека».
```

## Итерация 4. Качество и сдача

Цель — довести MVP до состояния «можно защищать»: сквозные тесты, доступность, release-сборка и документация. Дополнительные функции — только после того, как всё остальное зелёное. Разделы плана: 3, 8, 11.

**Состав**

- [x] Compose UI-тесты трёх сценариев раздела 8 с фейковым репозиторием
- [x] Тест миграции Room (базовый, от версии 1)
- [x] Доступность: описания изображений, зоны нажатия от 48 dp, проверка с крупным шрифтом
- [x] Покрытие data и domain не ниже 60% (Kover), Lint и detekt без ошибок, LeakCanary в debug
- [x] Release-сборка с R8: правила для kotlinx.serialization и Retrofit (запуск на устройстве — вручную, см. docs/AUDIT.md)
- [x] README: назначение, сборка, где взять токен, скриншоты
- [x] По желанию — GitHub Actions с тестами и Lint на каждый push
- [ ] По остатку времени — F-15…F-18, каждая отдельным коммитом

**Готово, когда:** выполнен чек-лист раздела 11 основного плана, кроме записки и презентации. Ручную часть — режим полёта, Accessibility Scanner, TalkBack — проверьте сами: Claude Code не видит экран устройства.

**Промпт**

```text

2. Исправь найденные пробелы.

коммит «Итерация 4: качество и сдача». Дополнительные функции не трогай.
```

## Итерация 5. Перевод на Java

Цель — тот же функционал, экраны, схема базы и сценарии тестов, но весь код на Java.

- [x] Java 17 вместо Kotlin: записи для моделей и DTO, sealed-интерфейсы, switch-выражения
- [x] Интерфейс — фрагменты, XML-разметка, ViewBinding, RecyclerView, Material Components
- [x] Navigation Component с XML-графом: вложенные графы вкладок, отдельный стек у каждой вкладки
- [x] LiveData и пул потоков вместо Flow и корутин; Paging 3 через `ListenableFuturePagingSource`
- [x] Gson вместо kotlinx.serialization, Glide вместо Coil, Room и Hilt через annotation processor
- [x] Схема Room версии 1 без изменений (проверено сравнением JSON и MigrationTest)
- [x] Все тесты перенесены на JUnit 4 + Robolectric, UI — Espresso; Checkstyle и JaCoCo вместо detekt, ktlint и Kover

**Промпт**

```text
Учитель просит сделать приложение на java. Твоя задача переписать его.
```
