# Кинополка — план курсового проекта

Sep 30, 2026 · @Natalie

## 1. Общие сведения

«Кинополка» — Android-приложение для поиска фильмов и сериалов через TMDB API и ведения личной медиатеки, которая работает без сети. Ключевое архитектурное решение: локальная база Room — единый источник данных для интерфейса, сеть только обновляет её.

**Цель:** разработать офлайн-first клиент TMDB на стеке Android Jetpack (Java, Material Components, MVVM) с каталогом по жанрам и локальными списками пользователя.

**Задачи:**

1. Проанализировать аналоги (Кинопоиск, IMDb, Letterboxd, TV Time) и сформулировать требования.
2. Изучить TMDB API v3: поиск, списки жанров, discover, детали, актёрский состав, рекомендации.
3. Спроектировать архитектуру, схему базы данных, навигацию и макеты экранов.
4. Реализовать сетевой слой, локальное хранилище, кэш и экраны.
5. Покрыть ключевую логику автотестами и провести ручное тестирование.
6. Оформить пояснительную записку и подготовить демонстрацию.

**Платформа:** Android 8.0 и выше (minSdk 26), targetSdk — последний стабильный на момент сдачи. Телефоны в портретной и альбомной ориентации; планшеты — без отдельной вёрстки.

**Границы проекта**

| Входит | Не входит |
| --- | --- |
| Поиск фильмов и сериалов, каталог по жанрам, подборки | Воспроизведение видео и трейлеров |
| Карточка контента с актёрами и похожими произведениями | Вход в аккаунт TMDB и синхронизация списков с ним |
| Списки «Хочу посмотреть», «Смотрел», «Избранное» | Собственный сервер, облачная синхронизация между устройствами |
| Офлайн-кэш метаданных и постеров сохранённых произведений | Отдельный раздел по актёрам (фильмография персоны) |
| Светлая и тёмная тема, русская локализация | Публикация в Google Play, монетизация, push-уведомления |

## 2. Функциональные требования

MVP — 14 требований, без которых проект не сдаётся; «Доп.» делаются при наличии времени. Требования пронумерованы, чтобы ссылаться на них в тестах и пояснительной записке.

| ID | Требование | Приоритет | Уточнение к исходному плану |
| --- | --- | --- | --- |
| F-01 | Поиск фильмов и сериалов одним запросом | MVP | Эндпоинт `search/multi`; результаты-персоны отфильтровываются. Запрос уходит через 400 мс после остановки ввода, от 2 символов, предыдущий запрос отменяется |
| F-02 | Фильтр «Все / Фильмы / Сериалы» | MVP | Работает и на главной, и в поиске; выбранное значение сохраняется при повороте экрана |
| F-03 | Бесконечная прокрутка результатов | MVP | TMDB отдаёт по 20 элементов на страницу; подгрузка через Paging 3 |
| F-04 | Список жанров из TMDB | MVP | Жанры фильмов и сериалов различаются — нужен объединённый справочник (раздел 4) |
| F-05 | Горизонтальные полки по жанрам на главной | MVP | 6–8 полок, по 20 элементов; кнопка «Все» ведёт на экран жанра |
| F-06 | Экран жанра с полным списком | MVP | Новый экран: сетка постеров с пагинацией и сортировкой «Популярные / По рейтингу / Новые» |

| F-08 | Карточка контента | MVP | Название, оригинальное название, год, тип, рейтинг и число голосов, жанры, описание; для фильма — длительность, для сериала — годы выхода и число сезонов |
| F-09 | Актёрский состав в карточке | MVP | Первые 10 актёров: фото, имя, роль |
| F-10 | Похожие произведения | MVP | Сначала `recommendations`, при пустом ответе — `similar` |
| F-11 | Управление статусом из карточки | MVP | Три действия: «Хочу посмотреть», «Смотрел», «В избранное». В исходном плане не было кнопки «Смотрел», хотя вкладка есть |
| F-12 | Моя полка с вкладками | MVP | «Хочу», «Смотрел», «Избранное»; работает без сети; счётчик на вкладке; сортировка по дате добавления, названию, рейтингу |
| F-13 | Удаление из списка | MVP | Свайп или меню, отмена через Snackbar |
| F-14 | Экран «О приложении» | MVP | Логотип и обязательная атрибуция TMDB, версия приложения |
| F-15 | Личная оценка 1–10 и дата просмотра | Доп. | Для записей со статусом «Смотрел» |
| F-16 | История поиска | Доп. | Последние 10 запросов, очистка |
| F-17 | Экспорт и импорт медиатеки в JSON | Доп. | Замена облачной синхронизации: перенос списков между устройствами |

**Правило статусов.** «Хочу посмотреть» и «Смотрел» взаимоисключающие: отметка «Смотрел» убирает произведение из «Хочу». «Избранное» — независимый флаг и может сочетаться с любым статусом.

## 3. Нефункциональные требования

Главное нефункциональное требование — предсказуемая работа без сети: медиатека открывается полностью, остальные экраны показывают последний кэш и не падают.

| ID | Категория | Требование | Как проверить |
| --- | --- | --- | --- |
| N-01 | Офлайн | «Моя полка» и карточки сохранённых произведений открываются без сети вместе с постерами | Режим полёта после сохранения 5 произведений |
| N-02 | Офлайн | Остальные экраны показывают кэш и баннер «Нет подключения»; при появлении сети данные обновляются сами | Переключение сети на эмуляторе |
| N-03 | Кэш | Срок жизни данных: жанры — 7 дней, полки и подборки — 6 часов, детали — 24 часа; дисковый кэш изображений — до 250 МБ | Unit-тест политики кэша с подменой времени |
| N-04 | Производительность | Холодный старт до 2 с, плавная прокрутка списков, постеры в размере `w342` для списков и `w500` для карточки | Android Studio Profiler, Macrobenchmark по желанию |
| N-05 | Устойчивость | Состояние экрана (запрос, фильтр, позиция) сохраняется при повороте и после уничтожения процесса | «Don't keep activities» в настройках разработчика |
| N-06 | Ошибки | Для каждого экрана есть состояния загрузки, пустого результата и ошибки с кнопкой «Повторить» | Ручной чек-лист + UI-тесты |
| N-07 | Локализация | Запросы с `language=ru-RU`; если русского описания нет — показывается английское с пометкой; все строки в `strings.xml` | Карточки малоизвестных сериалов |
| N-08 | Доступность | Описания изображений, зоны нажатия от 48 dp, корректная работа с крупным шрифтом и TalkBack | Accessibility Scanner |
| N-09 | Безопасность | Ключ TMDB хранится в `local.properties`, попадает в `BuildConfig` и не коммитится в Git | Проверка `.gitignore` и истории репозитория |
| N-10 | Приватность | Данные пользователя хранятся только на устройстве, без аналитики и сторонних SDK | Обзор зависимостей |

Ограничение, которое стоит честно указать в записке: ключ из `BuildConfig` можно извлечь из APK. Для учебного проекта это допустимо; в продукте запросы шли бы через собственный прокси-сервер.

## 4. Работа с TMDB API

Приложению достаточно девяти эндпоинтов TMDB API v3; главная техническая сложность — жанры фильмов и сериалов в TMDB имеют разные идентификаторы и частично разный состав.

**Эндпоинты**

| Назначение | Эндпоинт | Экран |
| --- | --- | --- |
| Справочник жанров | `genre/movie/list`, `genre/tv/list` | Главная, поиск, экран жанра |
| Поиск | `search/multi?query=&page=&include_adult=false` | Поиск |
| Подборка «В тренде» | `trending/all/week` | Главная |
| Популярное | `movie/popular`, `tv/popular` | Главная |
| Полки и экран жанра | `discover/movie`, `discover/tv` с `with_genres`, `sort_by`, `vote_count.gte=100` | Главная, экран жанра |
| Детали фильма | `movie/{id}?append_to_response=credits,recommendations,similar` | Карточка |
| Детали сериала | `tv/{id}?append_to_response=aggregate_credits,recommendations,similar` | Карточка |
| Изображения | `https://image.tmdb.org/t/p/{size}{path}` | Все экраны |

`append_to_response` загружает детали, актёров и похожие произведения одним запросом вместо четырёх. Фильтр `vote_count.gte` убирает из полок фильмы с рейтингом 10 от двух голосов.

**Объединённый справочник жанров.** Для фильтра «Все» пользователь видит один жанр, а приложение подставляет нужный id для каждого типа. Фрагмент соответствия:

| Жанр в приложении | id фильмов | id сериалов |
| --- | --- | --- |
| Комедия | 35 | 35 |
| Мультфильм | 16 | 16 |
| Драма | 18 | 18 |
| Боевик | 28 | 10759 «Боевик и приключения» |
| Фэнтези | 14 | 10765 «НФ и фэнтези» |
| Ужасы | 27 | нет — полка показывает только фильмы |

Соответствие хранится в коде как статическая таблица, названия жанров берутся из ответов TMDB на русском. При фильтре «Все» полка объединяет две страницы discover и сортирует их по популярности.

**Прочие правила**

- Авторизация — токен доступа на чтение (Read Access Token) в заголовке `Authorization: Bearer`, добавляется OkHttp-интерцептором вместе с `language=ru-RU`.
- Жёсткого лимита запросов нет, но TMDB ограничивает массовые обращения примерно 40 запросами в секунду; на ответ `429` клиент повторяет запрос с увеличивающейся паузой.
- Идентификаторы TMDB уникальны только внутри типа: у фильма и сериала может совпасть id. Ключ произведения везде — пара «тип + id».
- Атрибуция обязательна: на экране «О приложении» — одобренный логотип TMDB (менее заметный, чем логотип «Кинополки») и уведомление «This product uses the TMDB API but is not endorsed or certified by TMDB.»
- Некоммерческое использование API бесплатно, что соответствует формату курсового проекта.

Источники: [TMDB FAQ](https://developer.themoviedb.org/docs/faq), [TMDB Rate Limiting](https://developer.themoviedb.org/docs/rate-limiting).

## 5. Архитектура

MVVM с однонаправленным потоком данных: экран отправляет события во ViewModel и отображает один `LiveData<UiState>`, репозитории отдают данные из Room и обновляют их из сети.

&#91;embedded content: архитектура · 3 слоя, единый источник данных — Room\]

Постеры Glide загружает прямо из слоя интерфейса по `poster_path`, минуя репозитории; для записей медиатеки — из локального файла.

**Структура пакетов** (один Gradle-модуль, разбиение по функциям):

- `feature/home`, `feature/search`, `feature/details`, `feature/library`, `feature/genre`, `feature/about` — фрагмент, разметка XML, адаптеры списков, ViewModel, UiState.
- `core/network` — Retrofit API, DTO, интерцептор; `core/database` — сущности, DAO, миграции; `core/data` — репозитории и мапперы; `core/model` — доменные модели; `core/ui` — тема и общие компоненты (карточка постера, полка, заглушки).

Отдельный слой use case не обязателен: он нужен только там, где логика объединяет несколько репозиториев, например смена статуса с сохранением постера.

## 6. Модель данных Room

База разделена на кэш (можно удалить без потерь) и медиатеку пользователя (удалять нельзя); все таблицы произведений используют составной ключ «тип + id».

| Таблица | Первичный ключ | Основные поля | Назначение |
| --- | --- | --- | --- |
| `media` | `media_type`, `tmdb_id` | название, оригинальное название, описание, `poster_path`, дата выхода, рейтинг, число голосов, длительность или число сезонов, `cached_at` | Кэш метаданных произведения |
| `media_genre` | `media_type`, `tmdb_id`, `genre_id` | — | Связь произведения с жанрами (многие ко многим) |
| `genre` | `media_type`, `genre_id` | название, `cached_at` | Справочник жанров TMDB |
| `cast_member` | `media_type`, `tmdb_id`, `person_id` | имя, роль, `profile_path`, порядок | Актёры в карточке |
| `related_media` | источник, цель, `kind` | позиция | Рекомендации и похожие произведения |
| `feed_item` | `feed_key`, `position` | ссылка на `media`, `fetched_at` | Кэш подборок и полок главной (`trending`, `genre:28:movie`) |
| `library_entry` | `media_type`, `tmdb_id` | `watch_status` (NONE, WANT, WATCHED), `is_favorite`, `added_at`, `watched_at`, `user_rating`, `local_poster_path` | Медиатека пользователя |
| `search_history` | `query` | `searched_at` | История поиска (Доп.) |

**Почему статус, а не три таблицы.** Одно поле `watch_status` делает правило «Хочу / Смотрел» взаимоисключающим на уровне схемы, а флаг `is_favorite` не зависит от статуса. Запись удаляется, когда статус NONE и флаг снят.

**Политика кэша**

1. Экран всегда читает данные из Room через `LiveData`, сеть только обновляет таблицы.
2. Если `cached_at` старше срока из N-03, репозиторий показывает старые данные и обновляет их в фоне.
3. Раз в сутки WorkManager удаляет из `media` записи старше 30 дней, на которые не ссылается `library_entry`.
4. Поиск и полный список жанра не кэшируются в Room: они идут из сети через Paging 3, кэшируются только первые страницы полок главной.

**Постеры офлайн.** Дисковый кэш Glide вытесняет старые файлы, поэтому для записей медиатеки постер при добавлении сохраняется во внутреннее хранилище (`filesDir/posters`), путь пишется в `local_poster_path`. Так выполняется N-01 независимо от состояния кэша.

**Миграции.** `exportSchema = true`, схемы хранятся в репозитории, каждая смена версии покрывается тестом `MigrationTestHelper`. Удаление базы при миграции запрещено: пользователь потеряет медиатеку.

## 7. Экраны и навигация

К четырём исходным экранам добавлены два: «Экран жанра» (без него полки некуда развернуть) и «О приложении» (обязательная атрибуция TMDB). Нижняя навигация — «Главная», «Поиск», «Моя полка».

| Экран | Маршрут | Содержимое | Изменения к исходному плану |
| --- | --- | --- | --- |
| Главная | `Home` | Поле поиска, чипы «Все / Фильмы / Сериалы», «В тренде», полки жанров | Поле поиска — только точка входа: по нажатию открывается «Поиск» с фокусом ввода, логика поиска не дублируется |
| Поиск | `Search` | Поле ввода, те же чипы, список: постер, название, год, тип, 1–2 жанра | Жанры в результатах берутся из локального справочника по `genre_ids`; при пустом запросе — история поиска |
| Карточка | `Details(mediaType, id)` | Фон и постер, название, год, тип, рейтинг с числом голосов, жанры, раскрывающееся описание, актёры, похожие | Кнопки «Хочу / Смотрел» как сегментированный переключатель и отдельная кнопка избранного; при отсутствии сети показывается кэш |
| Моя полка | `Library` | Вкладки «Хочу», «Смотрел», «Избранное» со счётчиками; сортировка; фильтр по типу | Пустое состояние с кнопкой «Найти, что посмотреть»; удаление свайпом с отменой |
| Экран жанра | `Genre(genreKey, filter)` | Сетка постеров с пагинацией, сортировка | Новый экран |
| О приложении | `About` | Версия, логотип и уведомление TMDB, ссылка на themoviedb.org | Новый экран, открывается из меню «Моей полки» |

**Состояния.** Каждый экран описывается одним классом `UiState` с вариантами «загрузка», «данные», «пусто», «ошибка» и признаком офлайн-режима. На время загрузки показываются заглушки-скелеты вместо индикатора на весь экран.

**Навигация.** XML-граф Navigation Component: у каждой вкладки вложенный граф, аргументы — примитивы в `Bundle`. У каждой вкладки нижней навигации свой стек: возврат на вкладку восстанавливает прокрутку и открытую карточку. В карточку передаются только тип и id, данные она берёт из репозитория.

**Оформление.** Material 3, светлая и тёмная тема, динамические цвета на Android 12+, режим edge-to-edge. Постер без изображения заменяется заглушкой с названием.

## 8. Тестирование и контроль качества

Цель — не менее 60% покрытия строк в слоях data и domain и три сквозных UI-сценария; тесты привязаны к ID требований.

| Уровень | Что проверяется | Инструменты |
| --- | --- | --- |

## 9. Этапы работ

План рассчитан на 10 недель; MVP готов к концу 8-й недели, оставшиеся две недели — запас на тестирование, доработки и записку. Сроки сдачи уточнить у руководителя и привязать недели к датам.

1. **Неделя 1 — анализ.** Обзор аналогов, требования, получение ключа TMDB, пробные запросы в Postman. Результат: разделы 1–4 записки в черновике.
2. **Неделя 2 — проектирование и каркас.** Архитектура, схема БД, черновые макеты экранов. Проект: Gradle version catalog, Hilt, тема Material 3, навигация с пустыми экранами.
3. **Неделя 3 — сеть.** Retrofit, DTO, интерцептор токена и языка, обработка ошибок, тесты на MockWebServer.
4. **Неделя 4 — локальные данные.** Сущности и DAO Room, репозитории, политика кэша, тесты DAO.
5. **Неделя 5 — главная и жанры.** Объединённый справочник жанров, подборки, полки, экран жанра с пагинацией.
6. **Неделя 6 — поиск.** Поиск с задержкой ввода и Paging 3, фильтр типа, состояния пустого результата и ошибки.
7. **Неделя 7 — карточка.** Детали, актёры, похожие произведения, кнопки статусов и избранного.
8. **Неделя 8 — медиатека и офлайн.** «Моя полка», сохранение постеров, очистка кэша через WorkManager, «О приложении». Контрольная точка: все требования MVP.
9. **Неделя 9 — качество.** UI-тесты, ручной чек-лист, доступность, исправление ошибок; дополнительные функции — только если MVP стабилен.
10. **Неделя 10 — сдача.** Финальная версия записки, скриншоты, презентация, репетиция демонстрации.

Записку лучше вести параллельно с разработкой: каждый этап закрывается соответствующим разделом, а не переносится на последнюю неделю.

## 10. Риски

Самый опасный для защиты риск — отсутствие доступа к TMDB в аудитории; от него защищает офлайн-режим и заранее заполненная база.

| Риск | Последствие | Снижение |
| --- | --- | --- |
| TMDB недоступен в сети, где проходит защита | Демонстрация срывается | Перед защитой заполнить медиатеку и кэш; базовый адрес API вынести в конфигурацию сборки; записать резервное видео работы приложения |
| У части произведений нет русского описания или постера | Пустые блоки в карточке | Запасной запрос на английском с пометкой, заглушка вместо постера |
| Различия жанров фильмов и сериалов | Пустые или неверные полки при фильтре «Все» | Объединённый справочник жанров (раздел 4) и unit-тесты соответствия |
| TMDB меняет формат ответа | Ошибки разбора JSON | Необязательные поля в DTO, игнорирование неизвестных полей, отображение частичных данных |
| Ключ API попадает в публичный репозиторий | Блокировка ключа | `local.properties` в `.gitignore`; при утечке — перевыпуск ключа в кабинете TMDB |
| Недооценка сложности пагинации и офлайн-режима | Не хватает времени на MVP | Дополнительные функции только после контрольной точки 8-й недели |
| Ошибка миграции Room | Пользователь теряет медиатеку | Экспорт схем и тесты миграций, запрет деструктивной миграции |
| Несовместимость версий AGP, Gradle и библиотек | Проект не собирается | Версии в одном каталоге `libs.versions.toml`, обновление зависимостей одним коммитом, сборка в CI |

## 11. Пояснительная записка и критерии готовности

Записка повторяет ход работы: анализ, проектирование, реализация, тестирование; каждый раздел опирается на ID требований из разделов 2–3.

**Структура записки**

1. **Введение** — актуальность, цель, задачи, объект и предмет разработки.
2. **Анализ предметной области** — сравнение аналогов по функциям и офлайн-режиму, обзор TMDB API, обоснование стека.
3. **Проектирование** — требования, диаграмма вариантов использования, схема слоёв, ER-диаграмма базы, граф навигации, макеты экранов, диаграмма последовательности «открыть карточку без сети».
4. **Реализация** — сетевой слой, хранилище и кэш, объединение жанров, интерфейс; ключевые фрагменты кода с пояснениями.
5. **Тестирование** — методика, результаты автотестов, протокол ручных испытаний.
6. **Заключение**, список источников, приложения: ссылка на репозиторий, протокол испытаний, руководство пользователя со скриншотами.

**Критерии готовности к защите**

- [ ] Реализованы все требования MVP F-01…F-14
- [ ] «Моя полка» и сохранённые карточки работают в режиме полёта (N-01)
- [ ] Автотесты проходят, покрытие data и domain не ниже 60%
- [ ] Android Lint и Checkstyle без ошибок
- [ ] Атрибуция TMDB на экране «О приложении»
- [ ] Ключ API отсутствует в истории Git
- [ ] Release-сборка APK устанавливается на реальное устройство
- [ ] Медиатека и кэш заполнены на демонстрационном устройстве
- [ ] Записка, презентация и резервное видео готовы
